Contributing

Thanks for helping with rule-mcp. The short version: small fixes need no ceremony, structural change needs an ADR first.

Prerequisites

  • Node.js ≥ 20 (node --version)
  • pnpm 11+ (pnpm --version; the exact version CI uses is PNPM_VERSION in .github/workflows/ci.yml)
  • git

There is deliberately no packageManager field: the manifest guardrail bans it, so the version is not pinned there.

Setup

git clone https://github.com/pixu1980/rule-mcp.git
cd rule-mcp
pnpm install

pnpm install runs prepare, which installs the git hooks from .githooks/ as shims into .git/hooks/. To install them on demand: pnpm hooks:install. pnpm hooks:check fails when a clone is missing them.

Everyday commands

pnpm install          # dependencies (exact pins, frozen lockfile in CI)
pnpm test:all         # the whole suite - green before every pull request
pnpm lint             # eslint over bin/, src/, tests/
pnpm format           # prettier check (fix with pnpm format:fix)
pnpm census:check     # generated catalog docs are current (fix with pnpm census)
rule-mcp doctor # health report for your machine

How to contribute

  1. Read docs/README.md, then the numbered handbook chapters relevant to your change (docs/07-engineering-guides.md first for process).
  2. Open work is tracked in the issue tracker; plans inside the repo are deleted when fully executed or obsolete.
  3. Small fixes: open the pull request directly.
  4. Structural change: record an ADR in docs/adr/ first - a structural pull request without one is sent back for it.
  5. Keep prose English, American spelling.

Branches look like feat/short-description or fix/short-description. Commits follow Conventional Commits with a mandatory scope: type(scope): subject - the commit-msg hook rejects scope-less subjects. The allowed types live in one place, scripts/build/commit-types/index.mjs, and the hook, the PR-title check and the commit-lint CI job all follow it. There is no release type: version bumps use the chore(release) scope instead.

Maintainers sign commits and tags. Once, per machine:

git config commit.gpgsign true
git config user.signingkey <your-key-id>

Then tag releases signed: git tag -s v0.1.0. The release workflow refuses lightweight tags, and Vigilant Mode marks unsigned commits visibly on GitHub.

Every commit also carries a DCO sign-off trailer:

Signed-off-by: Your Name <you@example.com>

git commit -s adds it for you. The trailer asserts you wrote the change (or have the right to contribute it) under the Developer Certificate of Origin. There is no CLA; inbound contributions are licensed under the DCO. The hook rejects a commit without the trailer, and CI checks every commit in the pull request range.

Response times

Issues are triaged within 7 days; pull requests are reviewed within 14 days (see MAINTAINERS.md). If a week passes with silence, a polite ping on the issue is welcome.

Triage

Every issue gets a label from this set: bug, enhancement, good first issue, needs-triage, help wanted. New issues start at needs-triage until a maintainer routes them. An issue with no activity for 60 days gets a stale ping; 14 more silent days close it, and a comment reopens it at any time.
