Architecture decisions

./adr/ADR.md is every decision this project has taken: a chronological index, what each one says, and the themes they group into. Generated from the numbered files beside it, so it cannot fall behind them.

The ADR log is the only place history belongs. Everything else in docs/ describes what is true now.

Maintenance rules

  • Add long-form documentation to one of the numbered handbook files unless a separate file is justified.
  • 08 through 15 are generated. pnpm census derives them from the registries, and refreshes the fenced blocks inside 02, 05 and 07. Editing one by hand is work the next commit throws away; tests/docs/census-generated.test.mjs fails when a committed copy and the registry disagree.
  • No counts in this table. A number written beside a link is a claim with no generator behind it, and it is the copy that goes stale (ADR 048). The counts live in the generated documents that derive them.
  • Write what the code does, never what it did. A document that explains a change instead of a behavior is a second copy of an ADR, and it is the copy that goes stale.
  • Keep ADRs in docs/adr/. They are immutable decision records, and the one exception to the rule above.
  • When a plan is fully implemented, delete the plan file - no stale docs.
