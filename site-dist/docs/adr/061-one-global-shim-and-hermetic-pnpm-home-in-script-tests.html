061: One global shim, and hermetic PNPM_HOME in script tests

  • Date: 2026-09-07
  • Status: accepted
  • Tags: installer, cli, shim, testing, hermeticity
  • Author: Emiliano Pisu pisuemiliano.1980@gmail.com

Context

The recurring session-start failure spawn .../pnpm/bin/rule-mcp ENOENT had a reproducible cause: every test that shells out to install.sh/uninstall.sh spread process.env into the child, so the developer's real PNPM_HOME leaked in. uninstall.sh Phase 7 deletes $PNPM_HOME/bin/rule-mcp and install.sh's ensure_global_shim writes there - running the installer suite silently deleted the real shim (and once repointed it at a temp checkout). Separately, package.json declared two bin names for the same entrypoint - rule-mcp and rule-mcpd - and nothing consumes the second: the daemon wrapper of the same name lives at ~/.local/bin/ and is generated by the service installer, independent of the package bin.

Decision

Three layers. (1) Every test that spawns the shell scripts sets env.PNPM_HOME to a sandbox directory, enforced by a static gate (tests/cli/script-env-hermetic.test.mjs) that fails any spawning test whose source does not name PNPM_HOME. (2) uninstall.sh mirrors install.sh: RULE_MCP_SKIP_GLOBAL_LINK=1 skips the whole global-package phase, and the shim cleanup loops over both shim names so stale -mcpd shims are removed from machines that have them. (3) The rule-mcpd bin alias is deleted from package.json; the only package bin is rule-mcp. The Claude registration on this machine now runs node <repo>/bin/rule-mcp.js serve directly - no shim in the spawn path at all.

Consequences

Positive: the installer suite ran end to end with the real shim verified byte-identical before and after; the ENOENT class is closed twice over (nothing deletes the shim, and the Claude entry no longer depends on it); one bin name means one thing to heal. Negative: a machine that invoked rule-mcpd from the pnpm bin must switch to rule-mcp (the Login Items daemon wrapper at ~/.local/bin/rule-mcpd is unaffected).

What would end this

Publishing to a registry with a real global install (pnpm add -g), where pnpm owns the shim lifecycle and the hand-rolled shim heal becomes redundant.

Alternatives Considered

  1. Keep both bin names for compatibility - nothing consumes the alias, and every extra name is another shim that can go stale.
  2. Fix only the tests without the uninstall.sh skip flag - leaves the next non-sandboxed caller (another repo's suite, a CI job) free to reintroduce the deletion.
