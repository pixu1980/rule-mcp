054: Split review personas into per-operation commands (plan/audit/review)

  • Date: 2026-09-05
  • Status: accepted
  • Tags: personas, commands, prompts, surface
  • Author: Emiliano Pisu pisuemiliano.1980@gmail.com

Context

Each of the 7 active review personas shipped as one combined command, rule-plan-, whose template instructs one run to produce all three documents of the trio (docs/audits, docs/reviews, docs/plans). Running only one step meant the user invoked the combined command and mentally ignored two thirds of the contract; the per-role command body was also a generic routing recap, so the persona-specific operation contract only surfaced via the MCP prompt, which is suppressed on hosts that install clean slash commands.

Decision

Give each active role three slash commands - rule-plan-, rule-audit-, rule-review- (21 persona commands total), all generated from the same registry and all routing through the tools under the hood: the command body calls rule_tool_plan (with role and operation) to fetch the operation contract, and rule_tool_plan_docs for the trio bookkeeping. The template's header clause and operation section are now operation-aware; rule_tool_plan gained an optional operation parameter (default all three, unchanged for existing callers). Combined rule-plan- becomes plan-only.

Consequences

Positive: the user can run just the step they need; every command body names the exact tools to call, so agent behavior no longer depends on which surface the host exposes; proposed roles still stay out of the surfaces automatically. Negative: the command set grows by 14 names per agent (21 persona commands); the plan-only command no longer performs the audit/review pass in the same run, so users wanting the full trio run three commands or call rule_tool_plan without an operation. Tests pin the 48-prompt union and the parity fixture was regenerated to match.

What would end this

A single run of the trio stops being the user's default and per-step runs become a habit. Once that is routine, an explicit rule_tool_plan call with no operation is the combined contract and the three per-role commands could be collapsed back, or extended to a fourth operation (e.g. rule-close-*) if the lifecycle needs it.

Alternatives Considered

  1. Keep rule-plan-* only and run audit/review via rule_tool_plan explicitly (option 2: 7 commands)
  2. Ship rule-plan-* + rule-audit-* as commands, rule-review-* via tool only (option 3: 14 commands)
  3. Only the 4 core personas get commands (option 4: 12 commands)
