# Agent Infrastructure Guide

## Purpose

The `.agents/` directory centralizes everything an AI agent needs to work effectively on a project: golden rules, prompt templates, operative skills, code styleguides, and tool-specific configurations.

## Philosophy

1. **Single source of truth** - All agent-facing guidance lives in `.agents/`
2. **Link, don't duplicate** - Reference existing docs instead of copying
3. **Minimal surface** - Only what's needed, nothing speculative
4. **Discovery by convention** - Agents find `.agents/` by following standard structure

## The AGENTS.md Entry Point

Every project should have an `AGENTS.md` in the root. This is the first file an agent reads.

Structure:

1. **Golden rules** - 5-8 universal rules (read before writing, minimal diffs, match repo style, test what you change, etc.)
2. **Where to look first** - Table mapping needs to file locations
3. **Workflow** - The Spec → Plan → Implement → Test → Docs → PR flow
4. **Task routing** - What to read for each task type
5. **Definition of Done** - Checklist before PR
6. **Commands** - Project commands (install, dev, build, test, lint)
7. **Output format** - How to format responses (summary, files changed, how to verify, notes)

## Symlinks for Tool Configs

Tool-specific configs live in their canonical locations:

- `.github/` - GitHub Copilot
- `.cursor/` - Cursor editor
- `.claude/` - Claude Code

Symlinks in `.agents/` make them discoverable from the centralized location:

```bash
.agents/copilot/ → ../../.github/
.agents/cursor/ → ../../.cursor/
.agents/claude/ → ../../.claude/
```

This avoids duplication while keeping discovery simple.

## Prompt Design Principles

Good prompt templates are:

1. **Specific** - Name the phase, inputs, outputs, and format
2. **Minimal** - Short enough to read, complete enough to act
3. **Actionable** - End with a clear ask (code, plan, review)
4. **Link-based** - Reference other docs rather than duplicating

Example structure:

```markdown
# Feature Spec Prompt

## Inputs

- Issue/request description
- .context/ for domain knowledge

## Output

- Requirements statement
- Acceptance criteria (what "done" looks like)
- Assumptions documented

## Structure

1. Summary
2. Requirements
3. Acceptance criteria
4. Open questions
```

## Skill Management

### Adding a skill

1. Create `skills/rule-name/SKILL.md` with YAML frontmatter
2. Add supporting files (scripts/, references/, assets/, components/)
3. Run `node .agents/scripts/generate-skills-context.js` to update `SKILLS_CONTEXT.xml`

### Validating skills

Each skill must have:

- Valid frontmatter (`name`, `description`)
- Name matches folder name
- Description < 1024 characters
- Folder contains SKILL.md + optional subdirectories

### Skills context XML

Auto-generated by `generate-skills-context.js`. Contains all skills with:

```xml
<skill name="rule-skill-name" path=".agents/skills/rule-skill-name/SKILL.md">
  <description>Skill description</description>
  <files>
    <file path="scripts/_helper.js" />
    <file path="references/GUIDE.md" />
  </files>
</skill>
```

## Workflow Integration

The `.agents/` structure enables a clean workflow:

1. **Product/domain understanding**: `.context/` and spec docs
2. **Planning**: `.agents/prompts/implementation-plan.prompt.md`
3. **Implementation**: `.agents/skills/` + `.agents/instructions/` + `.agents/styleguides/`
4. **Testing**: `.agents/instructions/testing.instructions.md`
5. **Documentation**: `.agents/instructions/docs.instructions.md`
6. **PR creation**: `.agents/prompts/pr-description.prompt.md`

## CI Integration

Add these scripts to `package.json`:

```json
{
  "scripts": {
    "validate:agents": "node .agents/scripts/validate-skills.js",
    "generate:skills-context": "node .agents/scripts/generate-skills-context.js"
  }
}
```
