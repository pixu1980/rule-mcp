# Wizard Reborn — rule-architect Interview Restructure

> **Author**: Enterprise Architecture Review  
> **Status**: Draft  
> **Goal**: Eliminate redundancy, push all tech choices upfront, domain after, every choice→skill mapping explicit.

---

## 1. Current Problems

| # | Problem | Example |
|---|---------|---------|
| P1 | Tech choices spread across steps | Step 1 picks framework, Step 14 has deployment, Step 15 has security — should be one block |
| P2 | Domain content starts too early | Domain glossary, entities, personas appear before the full tech picture |
| P3 | Step 19 duplicates earlier steps | `step-99-placeholder-coverage` re-asks values already collected |
| P4 | Templates repeat each other | `project-context.md` copies content from specs/ |
| P5 | No clean CLI/Web parity | CLI and Web have drifted; step order is not enforced the same way |
| P6 | Some interview decisions better handled as skill calls | Database choice should call `rule-data-*`, not re-ask connection details |
| P7 | Option groups embed skill names in labels | `"label": "Express — rule-backend-express"` mixes display concern with routing |

## 5. `showIf` Dependency Graph

```
PROJECT_TYPE ─┬─ webapp ──┬─ FRONTEND_FRAMEWORK ──┬─ react ─┬─ META_FRAMEWORK (next/remix)
              │           │                        ├─ vue    ─┴─ META_FRAMEWORK (nuxt)
              │           │                        └─ svelte ─┴─ META_FRAMEWORK (sveltekit implicit)
              │           ├─ CSS_APPROACH
              │           ├─ BACKEND_FRAMEWORK ────┬─ !none ─── DATABASE
              │           │                        └─ API_STYLE (rest/graphql/trpc/ws)
              │           ├─ API_STYLE
              │           └─ DEVOPS (CI, Docker, Deploy, Monitor)
              │
              ├─ desktop ─┬─ FRONTEND_FRAMEWORK
              │           ├─ DESKTOP_FRAMEWORK (electron/tauri)
              │           ├─ CSS_APPROACH
              │           └─ DATABASE (sqlite/indexeddb for local)
              │
              ├─ mobile ──┬─ BACKEND_FRAMEWORK
              │            ├─ API_STYLE
              │            └─ DATABASE (sqlite)
              │
              ├─ backend ─┬─ BACKEND_FRAMEWORK
              │            ├─ DATABASE
              │            └─ API_STYLE
              │
              ├─ library  → (no sub-choices, minimal stack)
              ├─ agent    → (minimal stack)
              │
              └─ other    ── ARCHITECTURE_SKILL (free choice)
```

Every dependency uses `showIf` with:
- **Array**: `["webapp", "desktop"]` — field visible when value is any of these
- **Negation**: `{"not": "none"}` — field visible when value IS NOT this
- **Compound**: `{"PROJECT_TYPE": "webapp", "FRONTEND_FRAMEWORK": ["react", "vue"]}` — both must match
