## Evidence base (measured 2026-10-21)

### The router

`skills/rule-process/SKILL.md` is 56 lines: frontmatter, a nine-row table, a
Quick Selection block of seven lines, and a See also link. It is the smallest
area router in the repository (`rule-styleguide` is 247 lines, `rule-backend`
139). It has no `guardrails/` and no `guardrails:` frontmatter key.

Eight skills live under the area; the table lists seven. The missing one is
`rule-process-tdd`, recorded in `scripts/data/router-gaps.data.mjs` together
with five other area gaps. The table links two tools among the skills
(`/rule-compress`, `rule_tool_handoff`), which is the house style for this
router.

Quick Selection covers five of the eight children: `rule-process-changelog` and
`rule-process-tdd` are reachable only through the table.

### The hand-written columns already disagree with the generator

`scripts/reports/census/_format.mjs` derives a skill tool name as
`rule_tool_<name after rule-, dashes to underscores>`, so `rule-toolchain` maps to
`rule_tool_toolchain`. The dispatcher row for `rule-toolchain` says
`pix_toolchain`, and so do its eight children's rows. The same file truncates
descriptions, which is why the dispatcher's last column ends in `...`
everywhere. The columns were produced from the generator's shape by hand, which
is exactly the drift a generator removes.

The `Purpose` column of the area table is the only genuinely editorial text,
and it is already inconsistent: `rule-process-adr` uses the heading suffix
("Architecture Decision Records"), while `rule-process-readme` says "README
structure for open source and internal repos" where the skill heading says
"Write a good README". Generating that column means choosing the heading as
the source and fixing the two headings that do not match it.

## Open notes

- Generating the table turns the coverage test into a tautology: if the table is
  written from the directory, `router-child-listed` can only fail on a stale
  generated block that nobody regenerated. That is still worth checking (a
  forgotten `pnpm census` is the common failure) but the rule's value drops -
  the real defence becomes `census:check` in CI, not the rule.
- The dispatcher is not a skill and has no plan of its own
  (`docs/plans/skills/README.md`). Its 22 missing rows are folded into Phase 4
  because the generator is the same; if the owner prefers, that item moves to
  Phase 5 and the dispatcher stays stale for one more pass.
- `router-tool-name` needs a registry snapshot as `context.toolNames`. The
  snapshot exists only for the test surface today (`tests/fixtures/tool-surface.json`);
  the plan reuses it rather than starting the MCP server inside a rule.
- Quick Selection is the part a reader actually uses. Generating it from the
  table guarantees coverage but not priority: five lines of "need X, go here"
  carry more routing value than thirty rows of links, and the generator cannot
  tell which five those are. Phase 4 keeps an explicit ordering list in the
  child data rather than sorting alphabetically.
