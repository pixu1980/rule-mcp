# 171: Retire the plan-graph audit reference into an ADR and a handoff

- **Date**: 2026-10-24
- **Status**: accepted
- **Tags**: plans, audit, governance
- **Author**: Emiliano Pisu <pisuemiliano.1980@gmail.com>

## Context

`docs/plans/plan-of-plans-reference.md` was the audit that asked whether the plan graph allowed a linear implementation. It is `Status: done`, but it still carries eight follow-ups: F1 (apply the contract stage by stage), F2 (the Stage 3 order), F3 (the toolchain additions), F4 (one id per node), F5 (the five-line format), F8 (normalize the status line per stage), F9 (exempt the non-skill plans from the checkbox assertion) and the per-stage node list. The plan-graph review, `docs/reviews/plan-graph.md`, is the historical audit; the `plan-graph` role is already in `HISTORICAL_ROLES`.

## Decision

Record the audit and the eight follow-ups in this ADR and in handoff 27, then delete the reference file. The review and the historical role stay as history. The skills plan test keeps the retired path in its `NOT_A_PLAN` set; it reads the skills plan, not the reference file. The release PR #9 excluded the reference and is unaffected.

## Consequences

The audit's open items live in handoff 27 instead of a second plan file; the plan-graph review remains the evidence. The reference file is gone; the open child plans still link to it only as historical text. The ADR and handoff indexes are regenerated by the docs-numbering doctor.

## What would end this

The audit would need a file again if a new stage introduced a graph question the ADR and handoff cannot answer. The observation is a plan path that no ADR or handoff entry resolves.

## Alternatives Considered

1. Keep the reference (it is done and its eight follow-ups would stay split from the handoff)
1. Move only the follow-ups to the handoff (the audit evidence would be lost)
1. Delete the audit and the review (the history would be lost)
