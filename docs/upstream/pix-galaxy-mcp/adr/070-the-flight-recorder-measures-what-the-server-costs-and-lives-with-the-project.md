# 070: The flight recorder measures what the server costs, and lives with the project

- **Date**: 2026-09-03
- **Status**: accepted
- **Tags**: telemetry, flight-recorder, kpi, privacy, paths, git-hooks
- **Author**: Emiliano Pisu <emiliano.pisu@rule.com>
- **Updated in part by**: [ADR 082](083-everything-a-project-is-recorded-in-lives-under-the-home-directory-and-the-proje.md) - a recording lives under the home directory, not in the project; [ADR 074](075-caveman-compression-is-measured-at-its-own-step-and-it-is-a-small-real-saving.md), [ADR 078](079-compression-and-the-reminder-are-each-measured-at-the-step-that-causes-them.md) and [ADR 079](080-a-cache-hit-replays-output-it-does-not-save-tokens.md) - `cavemanRatio`, `reminderOverhead` and `savedBySource` are each measured differently now

## Context

Two benchmark reports of this server were written by hand, 1637 lines between them, from raw agent session logs. Everything that made them worth reading was missing from the recorder they were supposed to come from. The .flight export carried a replayable timeline and nothing else: no prompts, no model tokens, no cost, no peak context, no project outcome, and above all no answer to the one question asked of an MCP server, which is what its own results cost in the context window it writes into. The numbers were reachable but not recorded: the log kept prompt lengths and never the text, kept a guardrail failure count and never which rule failed, kept a saving figure and never the pair of measurements it came from. Meanwhile the server wrote into three directories in the user's home under an XDG-ish layout, and mixed every project's telemetry into one pile, so a cache hit rate averaged a machine rather than describing a codebase. ADR 046 had settled the telemetry design and its privacy clause forbade prompt text on disk; that clause is what made the recorder unable to say what was asked or how many times it had to be asked again.

## Decision

Record what was missing and keep it with the project. Per call the log now carries the result size in bytes with its token estimate, the argument size, the core-versus-final token pair, the skill mode, whether a resource was read instead of a tool called, the failing guardrail rule ids, the connecting MCP client, and the prompt verbatim. Prompt text is ON by default and RULE_MCP_NO_PROMPTS=1 takes it back out, which reverses ADR 046's privacy clause and supersedes it: the length alone answered the metrics and never answered the benchmark, and the protection that actually matters is unchanged, because remote sending stays off and the text goes to the user's own repository. Telemetry, exports and a per-project id move to ./.rule-mcp inside the project, while the daemon pid, its log, the result cache and the installation id stay in the home directory, which itself collapses from ~/.local/state, ~/.local/share and ~/.config into ~/.rule-mcp/{state,data,config} with a one-shot migration on first run. What the server cannot measure it reads rather than invents: agent-transcripts holds one adapter per coding agent whose usage is on disk in a parseable form, written against real files from pi, Claude Code, Codex and opencode, and every other agent is listed as unsupported with the reason instead of contributing a zero, because a zero gets averaged and a gap does not. A declared usage from pix_usage fills that gap and is stamped sidecar so it can never be confused with a figure read off disk; a transcript always wins. project-snapshot counts the outcome from the filesystem: lines and files per extension, components as directories with a barrel, ADRs, test files, source and dependency weight, and the tokensave graph reported present or absent. kpi folds the three sources into one block: the server's share of the model's tokens and of its cost, productivity per prompt and per minute, guardrail failures by rule, cache by tier, and an iteration count inferred from idle gaps that a transcript overrides and that is flagged estimated whenever it was not. The routing estimate still never merges into a measured total. The export is one .flight, version 2, keeping the FlightFile shape so the DevTools timeline still replays while ignoring the blocks it does not know, and it empties the log once the file is on disk, because an archive that leaves a copy behind double counts every comparison built from it. Because the recorder writes a directory into someone's repository, keeping it out of commits is the server's job: init creates the directory, adds the ignore rule and installs marked blocks in git's global hooks directory so a clone runs the full init and any other checkout re-asserts the rule, chained once to the repository's own hook so a global hook never shadows it, beside tokensave's blocks in the same file and never overwriting them.

## Consequences

The honest numbers cost something. A guardrail check on this repository's own source shows the same false positives on every committed file, so the new modules were accepted against that baseline rather than against a clean run. The compression ratio had to be renamed before it could be reported: measuring the core result against what actually leaves the server produced a negative "caveman compression", because finalizeResult appends the workflow reminder and routinely grows the output; the pair is now coreTokens and finalTokens, the compression is clamped at zero, and the growth is reported as reminderOverhead, which turns a false claim into a real cost the server can now see. Four unsupported agents are named in the code with their reasons, which is a list that will age and should be revisited rather than quietly trusted. The git hooks write a line into the .gitignore of every repository the user clones, which is deliberate and is the most invasive thing here; uninstall strips the blocks by marker and also purges the legacy home directories, since a machine that never ran the Node CLI never migrated. The prompt reversal means anyone who must not keep problem statements on disk has to set one variable, and the export puts every prompt in a single block precisely so a reader can drop one key. Surface grows by one tool to 106, which moved two committed assertions that count it.

## Alternatives considered

- **Keep prompts off disk and add them to reports by hand.** The status quo, and what produced 1637 lines of manual work.
- **Store telemetry in the home directory keyed by a project hash.** Keeps one pile and answers about a machine rather than a codebase.
- **Take the AI Flight Recorder SDK instead of its format.** The SDK exists to wrap a model client this server never calls.
- **Ship a local web dashboard.** Rejected in ADR 046 and still a server to run and secure for numbers a table carries.
- **Write per-project git hooks instead of global ones.** They cannot fire on a clone, because the clone is what creates the repository.
- **Self-ignore with a `.rule-mcp/.gitignore` holding a wildcard.** Mutates nothing of the project's own, but was not what was asked for.
