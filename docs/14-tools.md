### rule_tool

| `framework` | string | no       | -       | Optional framework hint (react, vue, svelte, angular, etc.) to bias routing |
| `path`      | string | no       | -       | Optional project path for auto-detecting framework                          |

### rule_tool_check

Verify code with deterministic guardrail checks, like lint pass, for any rule-mcp skill. Project mode checks graph rules; semantic mode offers advisory decision-model check. Re-check until allPass: true.

| Parameter             | Type            | Required | Default | Description                                                                                                                          |
| --------------------- | --------------- | -------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `skill`               | string          | yes      | -       | Target rule-mcp skill name                                                                                                           |
| `code`                | string          | no       | -       | Code to validate against guardrails (omit with mode=project)                                                                         |
| `framework`           | string          | no       | -       | Framework (react, vue, svelte, angular, solid, astro, vanilla)                                                                       |
| `fileName`            | string          | no       | -       | File name for naming convention checks                                                                                               |
| `isComponent`         | boolean         | no       | -       | Whether this is a component file                                                                                                     |
| `mode`                | string          | no       | -       | Check mode: 'scaffold' for project config files, 'project' for the graph guardrails, 'semantic' for the advisory decision-model rule |
| `allowedDependencies` | array of string | no       | -       | Manifest-derived package names allowed in imports                                                                                    |
| `projectDir`          | string          | no       | -       | Project root for mode=project (default: cwd)                                                                                         |
| `diagnostics`         | boolean         | no       | -       | Run the optional type-checker check in mode=project                                                                                  |

### rule_tool_compress

Sole compression engine (ADR 107): preprocess enriched prompts/contexts and postprocess model prose. Strip filler and leading articles, replace typographic characters with ASCII, convert British spelling to American. Code, inline spans, URLs and JSON are never touched. Prefer /rule-compress.

| Parameter  | Type                                     | Required | Default  | Description                                                                                                                       |
| ---------- | ---------------------------------------- | -------- | -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `text`     | string                                   | yes      | -        | Prose to compress. Code fences, inline code, URLs and JSON pass through untouched                                                 |
| `mode`     | `both` \| `compression` \| `fingerprint` | no       | `"both"` | both (default), compression (filler only), fingerprint (punctuation and spelling only)                                            |
| `fileName` | string                                   | no       | -        | Where the prose came from, when it came from a file. A sensitive name (.env, credentials, id_rsa, anything under .ssh) is refused |

| `path`    | string          | no       | `"."`    | Only files under this prefix are touched (default: the whole project)                                 |
| `mode`    | `lint` \| `fix` | no       | `"lint"` | lint: report what a fix would change. fix: write the deterministic fixes.                             |
| `dryRun`  | boolean         | no       | -        | Preview even in fix mode                                                                              |

### rule_tool_structural

Declare current task structural or architectural. next write asks for one confirmation, stating this summary, and rest of task proceeds without asking again. Call it before changing boundary, contract, dependency or layout, not for ordinary edits.

| Parameter    | Type   | Required | Default | Description                                                                                |
| ------------ | ------ | -------- | ------- | ------------------------------------------------------------------------------------------ |
| `summary`    | string | yes      | -       | What is changing and why it is structural, in one sentence the person confirming can judge |
| `projectDir` | string | no       | -       | Project root directory                                                                     |

### rule_tool_git

Audit the feature history and normalize it: base branch, merge base, commit range, Conventional Commit violations and merge commits. `reword` applies proposed messages. `linearize` removes merge commits. `squash` closes the feature as one commit and folds the feature's own ADRs and handoffs into one document each (deterministic concatenation, originals deleted, indexes rebuilt). The destructive actions need force:true to be proposed and confirm:true to run. Every rewrite verifies what changed and rolls back on an unexpected path.

| Parameter    | Type                                           | Required | Default   | Description                                          |
| ------------ | ---------------------------------------------- | -------- | --------- | ---------------------------------------------------- |
| `projectDir` | string                                         | no       | `"."`     | Project root (default: cwd)                          |
| `action`     | `audit` \| `reword` \| `linearize` \| `squash` | no       | `"audit"` | audit, reword, linearize, or squash                  |
| `force`      | boolean                                        | no       | `false`   | Enable a history-normalization proposal (--force)    |
| `confirm`    | boolean                                        | no       | `false`   | Required to run a rewrite; the confirmation gate     |
| `baseBranch` | string                                         | no       | -         | Override the detected base branch                    |
| `message`    | string                                         | no       | -         | For squash: the final type(scope): summary           |
| `rewrites`   | array of object                                | no       | -         | For reword: the message proposed for each commit sha |

### rule_tool_init

Prepare project for rule-mcp. Create central recorder directory under state dir. Install or integrate git governance: commit-msg gate and pre-push gate that enforce type(scope): subject. Install Husky only when Node project has no hook mechanism. Migrate leftover local.rule-mcp if present. Run tokensave init when it is installed. Recorder state is never written into repository. Pass noTokensave: true to skip tokensave.

| Parameter     | Type    | Required | Default | Description                 |
| ------------- | ------- | -------- | ------- | --------------------------- |
| `projectDir`  | string  | no       | -       | Project root (default: cwd) |
| `noTokensave` | boolean | no       | `false` | Skip tokensave init         |

### rule_tool_update

Force-update this local MCP server to newest release tag (checkout main, pull, reinstall), or fast-forward upstream branch when no tags exist yet. Also runs automatically (throttled, in background) on tool calls; call directly to update on demand.

Takes no parameters.

### rule_tool_handon

Verify the last session handoff before you resume: check its branch, commit range, files, ADRs and open work. Close completed audit, review and plan records first, then propose the next plan workstream for confirmation. Never re-run a claimed command.

| Parameter    | Type                 | Required | Default | Description                                                                                                                                                                                                        |
| ------------ | -------------------- | -------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `projectDir` | string               | no       | `"."`   | Project root directory                                                                                                                                                                                             |
| `file`       | string               | no       | -       | A specific handoff to read instead of the newest                                                                                                                                                                   |
| `list`       | boolean              | no       | `false` | List the handoffs and verify nothing                                                                                                                                                                               |
| `closeout`   | boolean \| `preview` | no       | `true`  | Archive completed audits/reviews/plans into ADRs, retire them from the plan indexes and delete the sources (default true). "preview" lists what would close out and writes nothing; false skips the sweep entirely |

### rule_tool_handoff

Close session or generate compressed handoff from ADRs and project context to resume work. Archive completed audit, review and plan records as ADRs and repair numbering first; pass closeout: false to diagnose without writing.

| Parameter         | Type                           | Required | Default     | Description                                                                                                                                                                                                        |
| ----------------- | ------------------------------ | -------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `projectDir`      | string                         | no       | `"."`       | Project root directory                                                                                                                                                                                             |
| `mode`            | `handoff` \| `close-session`   | no       | `"handoff"` | handoff: generate context summary. close-session: the same, with the session-close banner.                                                                                                                         |
| `closeout`        | boolean \| `preview`           | no       | `true`      | Archive completed audits/reviews/plans into ADRs, retire them from the plan indexes and delete the sources (default true). "preview" lists what would close out and writes nothing; false skips the sweep entirely |
| `includeContext`  | boolean                        | no       | `true`      | Include .context/ values                                                                                                                                                                                           |
| `includeAdrs`     | boolean                        | no       | `true`      | Include ADR summaries                                                                                                                                                                                              |
| `includeIdentity` | boolean                        | no       | `true`      | Include project identity                                                                                                                                                                                           |
| `includeGitDiff`  | boolean                        | no       | `true`      | Include git working tree diff                                                                                                                                                                                      |
| `includeGitLog`   | boolean                        | no       | `true`      | Include recent git log                                                                                                                                                                                             |
| `includeRoadmap`  | boolean                        | no       | `true`      | Include roadmap/docs scan                                                                                                                                                                                          |
| `compress`        | boolean                        | no       | `true`      | Aggressively compress output (default: on)                                                                                                                                                                         |

### rule_tool_gateway

Single-entry orchestrator: make routing decision, load skill evidence, verify code with lint-like guardrail checks, and return receipt. Use this as primary entry point instead of calling rule-mcp + skill tools separately. returned receipt must be passed to rule_tool_apply when writing files.

| Parameter   | Type                      | Required | Default | Description                                                                                           |
| ----------- | ------------------------- | -------- | ------- | ----------------------------------------------------------------------------------------------------- |
| `prompt`    | string                    | yes      | -       | Complete coding request                                                                               |
| `code`      | string                    | no       | -       | Code to validate against guardrails (single file)                                                     |
| `files`     | array of object \| object | no       | -       | Files to validate - yields a path-bound receipt, required for multi-file writes                       |
| `path`      | string                    | no       | -       | Project path for framework auto-detection                                                             |
| `framework` | string                    | no       | -       | Target framework (react, vue, svelte, angular, solid, astro, vanilla, express, fastify, nestjs, hono) |

### rule_tool_apply

Write files to disk after rule_tool_gateway validation. Needs valid receipt from rule_tool_gateway proving that code passed all guardrails. receipt is tied to exact code hash - modified code will be rejected. Use dryRun=true (default) to preview without writing.

| Parameter | Type            | Required | Default | Description                                                         |
| --------- | --------------- | -------- | ------- | ------------------------------------------------------------------- |
| `files`   | array of object | yes      | -       | Array of files to create/write                                      |
| `receipt` | string          | yes      | -       | Receipt token from rule_tool_gateway that validated this exact code |
| `path`    | string          | no       | `"."`   | Project root directory                                              |
| `dryRun`  | boolean         | no       | `true`  | Preview without writing (default: true)                             |
